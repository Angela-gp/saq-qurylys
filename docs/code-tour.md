# Короткий разбор кода

## Баллы и зоны

`backend/app/domain/scoring.py` задаёт веса факторов и чистую функцию `calculate_score`. В сумму входят только доказательства со статусом `fact` или `confirmed`. Повтор одного кода не увеличивает вес. Красная зона требует 60 баллов, подтверждённые R1 и R2; жёлтая начинается с 25. `None`, `not_checked` и `no_data` не создают R1.

## Публикация → гипотеза → подтверждение → пересчёт

`backend/app/api/routes.py` создаёт публикацию и вызывает `extract_payment_offer` из `backend/app/ai/extractor.py`. Извлекатель выбирает LLM при настроенном ключе, иначе локальные правила `backend/app/ai/rules_extractor.py`. Проверка цитаты гарантирует её точное присутствие в исходном тексте. Найденная фраза записывается как `ai_hypothesis`, поэтому скоринг её пока не включает.

При ручном подтверждении endpoint проверки доказательства меняет статус на `fact`, сохраняет автора, время и ссылку-источник и записывает событие аудита. Ответ API заново рассчитывает балл из текущих доказательств; интерфейс обновляет карточку ЖК. Так достигается переход 0 → 25 после подтверждения R2.

## Статусы сигнала

Статусы и разрешённые переходы задаются в `ALLOWED_TRANSITIONS` в `backend/app/api/routes.py`: `draft → in_review → confirmed` или `returned`, затем `returned → in_review`. Нельзя подтвердить карточку без факторов. Каждый переход добавляет автора, время и комментарий в историю карточки и отдельную запись аудита. Из `confirmed` обратного перехода нет.

## Данные

SQLAlchemy модели находятся в `backend/app/models.py`; соединение с SQLite и создание таблиц — в `backend/app/database.py`. Папка `backend/seed/` содержит только явно загружаемые контрольные сценарии. При обычном старте база создаётся пустой.
