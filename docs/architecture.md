# Архитектура SAQ QURYLYS

## Данные

FastAPI выполняет синхронные операции SQLAlchemy 2 с SQLite. Таблицы создаются при старте; новая база пуста до импорта или явного seed. Основные таблицы: `housing_objects`, `publications`, `evidence`, `signals`, `audit_log`, пользователи и записи ручных проверок источников. Демо-seed содержит вымышленные записи и загружается отдельно от реальных импортов.

Вход использует подписанную cookie-сессию Starlette. Пароли пользователей seed сохраняются как Argon2-хэши; роли `analyst` и `observer` проверяются backend-зависимостью для всех `/api` маршрутов. Автор аудита берётся из вошедшей сессии, поля автора из запроса для этого не используются. Публичной регистрации нет. Ограничение попыток входа хранится в памяти процесса.

## Поток анализа объявления

1. Аналитик вставляет текст и, при желании, URL и площадку.
2. Извлекатель ищет фразы оплаты локальными правилами или вызывает совместимый с OpenAI API endpoint.
3. Для ответа LLM проверяется, что цитата буквально входит в исходный текст. При отсутствии цитаты гипотеза ненадёжна.
4. RapidFuzz выдаёт кандидатов по названию застройщика или ЖК. Автоматической привязки нет.
5. После ручного выбора объекта приложение создаёт гипотезу R2; R3 предлагается для объекта со статусом строительства.
6. Только действие аналитика `fact` переводит гипотезу в подтверждённый фактор и пересчитывает оценку. Отклонение сохраняется в аудите.

## Источники

`SourceAdapter` задаёт контракт для подключаемых источников. Ashyq адаптер запрашивает метаданные через публичный API и сообщает о недоступности как `no_data`; отсутствие ответа не означает отсутствие разрешения. Записи загружаются из выбранного пользователем CSV/XLSX через конфигурацию колонок, валидируются и дедуплицируются. Импорт проверен только на искусственном CSV из `data/sample/`; реальная выгрузка целиком не проверялась. Остальные реестры представлены ссылками для ручной проверки, автоматического получения их записей нет.

Telegram импорт принимает `result.json` из экспорта Telegram Desktop для публичного канала. Парсер проверен на искусственном JSON образце, не на реальном экспорте. Бота, токенов и автоматической синхронизации нет; лишние поля экспорта (включая авторов) отбрасываются.

## Оценка и карточка

Модуль `domain/scoring.py` не зависит от FastAPI и SQLAlchemy. Он учитывает только статус `fact`/`confirmed`, ограничивает сумму ста баллами, применяет порог зон и возвращает факторы с источниками. Уникальный код фактора даёт очки один раз. Карточка фиксирует снимок оценки на момент создания; переходы статусов ограничены черновиком, проверкой, подтверждением и возвратом с комментарием.

## API

Основные маршруты: `GET /api/objects`, `GET /api/objects/{id}`, `POST /api/objects`, `POST /api/publications`, `PATCH /api/evidence/{id}/review`, `PATCH /api/objects/{id}/legal-basis`, `POST /api/import/ashyq`, `GET /api/sources`, `GET/POST /api/signals`. Полная интерактивная схема доступна в `/docs`.

## Клиентское приложение

React/TypeScript интерфейс содержит обзор с Leaflet-картой, реестр и карточку ЖК, рекламу, сигнальные карточки и источники. Переводы RU/KK находятся в `frontend/src/locales/ru.json` и `kk.json`; даты и числа форматируются через `Intl`. Светлая/тёмная темы сохраняются локально. Guided Tour использует `data-tour` цели, пропускает отсутствующие элементы и не меняет данные. Печатная версия открывает системную печать браузера; PDF не генерируется backend-сервисом.

## Проверка и границы

Backend и frontend имеют автоматические тесты. Локальный извлекатель правил тестировался; опциональный LLM путь реализован, но не проверялся с настоящим API-ключом. OCR отсутствует. Юридический казахский перевод ещё должен проверить носитель языка.
