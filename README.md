# SAQ QURYLYS

Прототип системы мониторинга открытых сведений о строящихся жилых объектах Казахстана. Он объединяет импорт реестра, проверку источников, разбор рекламных текстов, журнал решений и сигнальные карточки. Система не выносит юридических заключений: гипотезы и правовые основания подтверждает аналитик.

## Запуск на Windows

Требуются Python 3.11+ и Node.js 20+.

Для запуска сценариев A/B/C жюри выполните **`make seed`** после установки зависимостей. Команда загружает 8 вымышленных ЖК и 12 публикаций. В Windows без Make используйте `python -m backend.seed.seed`. В интерфейсе обзора есть такая же кнопка «Загрузить ДЕМО-данные». На чистой установке база остаётся пустой, пока вы явно не загрузите seed.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m backend.seed.seed
```

В первом терминале запустите API:

```powershell
python -m uvicorn backend.app.main:app --reload
```

Во втором терминале запустите веб-интерфейс:

```powershell
cd frontend
npm install
npm run dev
```

Откройте адрес Vite, обычно `http://localhost:5173`. Автодокументация API доступна по адресу `http://127.0.0.1:8000/docs`. SQLite файл создаётся автоматически при запуске в `backend/data/saq_qurylys.db`; таблицы создаются пустыми. Вымышленные записи не загружаются автоматически.

### Подключить демонстрационный сценарий

Демо набор полностью вымышлен, каждая запись помечена «ДЕМО» и не содержит действительных БИН. Он нужен только для прогона сценариев A/B/C и показа интерфейса. Запускайте его явно:

```powershell
python -m backend.seed.seed
```

Команду можно запускать повторно: она пересоздаёт только записи ДЕМО. Импортированные реальные строки сохраняются.

## Реальные данные

На странице «Обзор» или «Реестр» загрузите CSV/XLSX из [набора Ashyq Data о долевом участии](https://ashyq.data.gov.kz/dataset/magda-ds-b80110e9-218a-42ba-b8c8-01fa5e4c82c8). Импорт читает файл, который выбрал аналитик, ограничивает его 5 МБ и 25 000 строками, пропускает уже загруженные записи и пишет источник в журнал аудита. Импорт записи не доказывает наличие или отсутствие разрешения.

Проверка Ashyq на 16 октября 2026: официальный API метаданных доступен; он описывает поля `object_id`, `object_location`, `builder_name`, `authorized_org_name`, `object_address`, `date_start`, `date_end`, `permission_number`, `time_modif`. Сам CSV-файл вручную получить в этой среде не удалось: файловый хост вернул самоподписанный TLS-сертификат, а проверку TLS приложение не отключает. Импортёр проверен на записи, собранной по опубликованной схеме, и на пустом образце заголовков [`docs/samples/ashyq-schema.csv`](docs/samples/ashyq-schema.csv), но не на реальной выгрузке. Это проверка соответствия схеме, не подтверждение совместимости со всеми вариантами файла. Сопоставление значений и их актуальность аналитик проверяет по первоисточнику.

API показывает доступность метаданных Ashyq. Прямую загрузку набора можно выполнить вручную с официальной страницы: в текущей конфигурации хост CSV может отдавать некорректный TLS-сертификат, поэтому приложение не отключает проверку TLS. Для Homeportal, E-License, Qazreestr, eQurylys, eGov, КГД, РСП, кадастровой карты и РНУ оставлены ссылки для проверки человеком. Автоматический доступ к закрытым или нестабильным интерфейсам не имитируется.

## ИИ и извлечение

Проверено в режиме правил; LLM-режим реализован, но не тестировался с ключом. Без ключа работает локальный словарь русских и казахских формулировок. Опционально задайте `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL` в `.env` для OpenAI-compatible chat completions. LLM используется только для извлечения цитаты. Цитата проверяется на точное присутствие в тексте объявления. При сетевой ошибке включаются локальные правила. Ни API ключ, ни полный текст рекламы не записываются в журнал аудита.

Разбор рекламы не устанавливает связь с ЖК сам по себе. Аналитик выбирает объект вручную. Обнаруженная формулировка и связь с активным объектом создают гипотезу R2/R3; баллы появятся только после явного подтверждения цитаты.

## Оценка

Факторы: R1 — 35, R2 — 25, R3 — 10, R4 — 15, R5 — 10, R6 — 5 баллов. Повторные подтверждения одного кода не складываются. R1 создаётся только после проверки правового основания с URL источника. Неизвестное или недоступное состояние не считается R1. Красная зона требует одновременно не менее 60 баллов, подтверждённые R1 и R2; жёлтая начинается с 25; ниже — зелёная. Границы и контрольные сценарии проверяются тестами.

## Сквозной сценарий для защиты

1. Запустите приложение, затем выполните `python -m backend.seed.seed`, чтобы явно загрузить контрольные ДЕМО-данные.
2. В реестре откройте **ЖК Өскемен River**: сценарий B показывает **70 баллов, красную зону** и факторы R1, R2, R3. Вымышленные строки помечены ДЕМО и не являются сведениями о реальном ЖК.
3. На «Обзоре» нажмите «Добавить объект», создайте объект «Пробный ЖК» и откройте страницу «Реклама».
4. Введите текст `Внесите депозит 500 000 за бронь квартиры в строящемся доме.`, укажите тестовый адрес публикации `https://example.org/demo-ad`, выберите «Пробный ЖК» и нажмите «Извлечь условия оплаты».
5. Откройте карточку «Пробный ЖК». R2 появится как гипотеза, а балл останется **0**. Добавьте ссылку на источник и нажмите «Подтвердить»: балл станет **25**, зона — **жёлтая**.
6. На странице «Сигналы» создайте карточку для ЖК Өскемен River, передайте её на проверку и подтвердите. Оценка карточки — **70**, зона — **красная**. Кнопка «Печать / PDF» вызывает системную печать браузера.

Повторный запуск seed пересоздаёт контрольные демо-объекты и связанные с ними записи. Для повторения шага 5 создайте новый тестовый объект.

## Что реализовано и что нет

**Реализовано:** локальная база SQLite; скоринг только подтверждённых факторов; зоны с условиями R1/R2 для красного уровня; объяснение балла со ссылками на записи доказательств и цитатами; изолированный what-if расчёт для ожидающих проверки факторов (не меняет текущий балл); русско-казахские правила извлечения цитат; ручное подтверждение гипотез со ссылкой; переходы статусов сигнала с автором, временем и аудитом; явные ДЕМО-сценарии A/B/C; импорт CSV/XLSX по схеме; карта Leaflet для записей с координатами.

Контрольные цитаты A/B/C являются вымышленными и берутся из текстов соответствующих ДЕМО-публикаций; тест проверяет совпадение цитаты и текста. Ссылки на seed-публикации используют `example.invalid` и не ведут на реальные объявления.

**Пока не реализовано или не проверено:** автоматическое получение записей из большинства реестров; импорт реального скачанного CSV Ashyq; проверка LLM с ключом; OCR; полноценная локализация интерфейса на казахский; пользовательская аутентификация; сохранение PDF в обычном Chrome/Edge. Печать вызывает `window.print`, но её системный диалог и итоговый PDF здесь не проверены. Не выдавайте эти пункты за готовые интеграции.

## Ограничения прототипа

- Доступ к карточке аналитика сейчас локальный, без аутентификации и разделения ролей. Не публикуйте сервис в открытом интернете с персональными или служебными данными.
- Сигналы и импорт хранятся в локальном SQLite. Это одиночная пользовательская база, не многопользовательская транзакционная система.
- Статусы источников отражают только подключённые функции приложения; «ручная проверка» означает обычную ссылку на первоисточник.
- Координаты не вычисляются по адресу. На карте появляются только координаты, пришедшие из записи.
- Экспорт карточки использует браузерную печать; в диалоге печати можно выбрать «Сохранить в PDF».
- Импорт Ashyq проверен на структурной записи по официальной схеме, но не на скачанном реальном CSV из-за ошибки TLS на файловом хосте.
- LLM-путь не запускался с действительным API ключом; проверен локальный режим правил.
- Сквозной сценарий пройден в браузере в локальном окружении. Кнопка печати вызывает `window.print`, но проверить системный диалог Chrome/Edge и сохранить PDF из доступной браузерной среды не удалось; print CSS не считается подтверждённым обычной печатью, PDF-пример не приложен.
- В автоматизированной среде нет средства записи экрана. Для записи предусмотрен тайминг и порядок действий в [`docs/demo-runbook.md`](docs/demo-runbook.md).

Перед публикацией репозитория проверьте локальные изменения и удалите `.env` и файлы базы, если они появились. Они уже добавлены в `.gitignore`.
